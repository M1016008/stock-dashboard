# 事前登録: X→Y→X 型の遷移とその後の値動き (2026-11-11)

この文書は、データを見る前に条件を固定するための事前登録である。条件はオーナーが 2026-11-11 に決めた。
「オーナー決定」の節はオーナーの言葉のとおり、「固定した細部」の節は、オーナー決定を実行するために
集計の前に固定した取り決め。この文書が main に Merge されるまで、この研究の集計は始めない。
Merge の後に条件を変える場合は、変更の理由と日付をこの文書に追記し、オーナーの承認を得る。

## オーナー決定

1. 定義: 同じ 6 桁の状態が続く日々を 1 つにまとめ、連続する 3 つの状態のうち 1 つ目と 3 つ目が同じで
   2 つ目が違うもの (X→Y→X)。Y の滞在日数は問わず、記録する。シグナルは 3 つ目の X に入った日
   (その日に知り得た情報のみ)。買うのは翌営業日の終値。
2. 対象: 日本株、Discovery 期間 (2022-12-30 まで)。STATUS に記録した除外の基準をすべて適用する。
3. 期間: 5・10・15・20 営業日を報告する。主な期間は 10 営業日と 20 営業日とし、それぞれ別に判断する。
4. 測るもの: リターンの中央値、10・25・75・90% 点、プラスで終わった割合、期間中の最大の上昇幅・下落幅と
   その到達日数。LONG と理論上の SHORT。
5. 市場全体の値動きは差し引かず、そのままのリターンで比べる。
6. 比較の相手: X→Y→Z 型 (Z≠X)。参考として全イベントの平均も示す。
7. 同じ銘柄で 20 営業日以内に続いたイベントは、最初の 1 件だけを数える。
8. 「差がある」と判断する条件 (10 営業日・20 営業日それぞれで、すべて満たすこと):
   - X→Y→X 型と X→Y→Z 型の中央値の差について、95% の信頼区間が 0 をまたがない。
   - Discovery 期間を 2008〜2012 年、2013〜2017 年、2018〜2022 年に分けても、すべて同じ向きの差が出る。
9. 内訳 (探索として報告し、結論には使わない): X の種類ごと、当時の市場区分ごと。市場区分は当時のもの
   (2022 年 4 月より前は旧区分) を使い、今の区分に置き換えない。当時の区分がわからない期間は「不明」とする。
10. その後: 8 を満たした場合だけ、同じ条件のまま Validation 期間で確かめることを提案する
    (オーナーの明示承認が必要)。満たさない場合も「差がなかった」という結論として記録する。

## 固定した細部

### 使うデータ (読み取り専用。封印 C の資産は変更しない)
- 状態の並び: E039 の土台 `v5/E039-JP-scale-consistent-phase1b0-foundation/events.sqlite` の
  `events` 表の 3 状態の入りのイベント (`length = 3`、`event_type` が入り)。`sequence_key` が `A>B>C`、
  `signal_date` が C に入った日、`dwell_b` が Y の滞在日数。6 桁の状態の作り方・null の扱い・
  データの途切れ (`block_id`) は E039 の定義のまま変えない。
- 株価: Discovery の元データ `six-stage-discovery-source-export-20261025T211500JST-v2-r2.incomplete/jp-discovery-ohlcv.sqlite`
  (`six-stage-real-data-contract.ts` が hash を照合するもの)。
- X→Y→X 型は A = C、X→Y→Z 型は A ≠ C。B ≠ A かつ B ≠ C は状態のまとめ方から必ず成り立つ。
- Y の途中から始まった (左側が途切れた) イベント (`left_censored_b = 1`) は、Y の滞在日数が分からないため除く。
  X (1 つ目) の滞在日数は問わないので、`left_censored_a` は条件にしない。
- 有効な 6 桁の状態は長い MA (月足 B は 25 か月) が揃ってから始まるため、2008〜2012 年の区分は
  実質的に 2010 年以降になる見込み。各区分の最初と最後のシグナル日と件数を報告する。

### 買いと結果の計算
- 営業日は、その銘柄の売買のある行で数える (シグナルの日の次の行が「翌営業日」)。
- 買値は翌営業日の終値。h 営業日後の結果は、買った日の次の行から数えて h 行目の終値。
  リターン = h 行目の終値 / 買値 − 1。
- 最大の上昇幅 = 買った日の次の行から h 行目までの高値の最大 / 買値 − 1。最大の下落幅は安値の最小で同じ。
  到達日数は、その最大・最小が最初に出た行の番号 (1〜h)。
- 理論上の SHORT: リターンは LONG の符号を反転したもの。最大の上昇幅は LONG の最大の下落幅を反転したもの
  (下落幅も同様)。手数料・貸株料・配当は含めない (そのままのリターン)。
- 買値が無い・0 以下の場合はそのイベントを除き、件数を報告する。h 行目が 2022-12-30 より後になる場合は、
  その期間だけ結果が無いものとして扱い、件数を報告する。

### 除外 (STATUS「日本株の研究 Store (E039) を使うときの除外」)
- 結果の期間 (買った日から 20 営業日後まで) の中に、10 営業日を超えて売買の無い空白があるイベント。
- シグナルの日から買う日までに、10 営業日を超えて売買の無い空白があるイベント。
- 分割の補正漏れが確認された 19 銘柄のすべてのイベント。
- 空白の営業日は、元データでいずれかの銘柄に売買がある日で数える。
- 除外を先に適用し、その後に 7 (20 営業日以内の重複) を適用する (除外したイベントが、残すべき
  イベントを消さないようにするため)。

### 重複の扱い (オーナー決定 7)
- X→Y→X 型と X→Y→Z 型で、それぞれ別に適用する。
- 同じ銘柄のイベントをシグナル日の順に並べ、最後に数えたイベントのシグナル日から、その銘柄の
  20 行以内 (行の番号の差が 20 以下) に入ったイベントは数えない。
- 参考の「全イベントの平均」は、両方の型を合わせた集合に同じ規則を適用したもの。

### 信頼区間 (オーナー決定 8)
- 差 = X→Y→X 型の中央値 − X→Y→Z 型の中央値 (LONG のリターン)。SHORT の差は符号が反転するだけなので、
  判断は LONG の差で 1 回行う。
- 既存の研究コード (`lib/research/six-stage-statistics.ts`、ブランチ `codex/six-stage-transition-research-v3`
  の commit `dbe2963`) と同じ方法で計算する。
  - 銘柄のまとまりの bootstrap: 銘柄を単位に、銘柄の数だけ復元抽出し、両方の型の中央値の差を計算する。
  - 時期のまとまりの bootstrap: シグナル日の年月 (YYYY-MM) を単位に、同じように計算する。
    20 営業日の結果の期間は近い日どうしで重なるため、既存コードの「シグナル日」ではなく「年月」を単位にする。
  - 各 2,000 回、乱数の種は 20261111。95% 区間は 2.5% 点と 97.5% 点。
  - 判断に使う区間は、2 つの区間を両方含む保守的な区間 (下限は小さい方、上限は大きい方)。
- 区分ごとの「同じ向き」は、各区分の中央値の差 (点推定) の符号が、全期間の差の符号と同じこと。
  差がちょうど 0 の区分は「同じ向きではない」とする。

### 内訳 (探索、結論には使わない)
- X の種類ごと: X の 6 桁ごとに、件数・中央値・プラスで終わった割合を示す。件数による足切りはしない。
- 市場区分ごと: シグナル日の当時の市場区分を使う。2016-11-11 以降は、J-Quants の上場銘柄一覧
  (`/equities/master` の日付指定) で、その日の区分を取る。それより前は、DB に当時の区分の履歴が
  残っていれば使い、無ければ「不明」とする (残っているかは 11/15 の Backup のコピーで確かめる)。
